# 고정 지형과 바닥 꾸미기 구현 기록

작성: 2026-10-19, AI 구현·기록. 사용자는 고정 Landscape+Static Mesh, 시설·바닥 꾸미기, 순차 구현 후 빌드·실행 검증을 요청했다. 아래 세부 구현 선택은 AI의 MVP 판단이며 사용자 직접 구현이나 최종 검토로 표현하지 않는다.

## 초보자를 위한 구성

- Landscape는 넓은 기본 땅이다. 기존 6개 지형 레이어와 계절 설정을 유지한다.
- Static Mesh는 미리 만든 입체 물체다. 평평한 언덕 상판, 절벽, 경사로를 고정 배치한다.
- SurfaceId는 땅 한 조각의 고유 번호다. 같은 화면 위치라도 언덕 위와 아래를 구별한다.
- PaintDomainId는 그 표면에 칠한 그림의 고유 번호다. 서로 다른 층의 도색을 분리한다.
- 머티리얼은 화면에 보일 색·질감을 계산한다. 저장 원본은 CPU의 도색 비율이고 GPU 텍스처는 표시용 복사본이다.
- 시설과 바닥 타일은 별도 목록으로 저장한다. 장식 타일은 시설의 기초 구조물이 아니므로 타일을 보관해도 시설은 유지한다.
- 기존 주인공은 NavMesh가 아닌 칸 기반 길찾기를 사용했다. 이번 구현은 칸의 각 높이를 별도 노드로 만들고 경사로 연결을 검사한다.

## 수정이 시작된 문제

기존 배치는 수평면의 마우스 위치와 시설 중심의 지면 높이에 의존했다. 언덕 가장자리에서는 중심이 지지되어도 시설 끝이 뜰 수 있고, 같은 XY의 다른 층을 구별하기 어려웠다. 배치 중 실제 액터를 옮기는 방식도 취소·충돌 검사와 섞일 수 있었다.

표면을 직접 선택하고 바닥 전체를 검사하도록 변경했다. 별도 미리보기 액터를 움직이고 확정할 때 원래 시설을 이동한다. 시설 GUID와 생산 작업은 보존한다. 길찾기는 높이별 고정 지형 그래프와 시설 점유를 함께 검사한다.

## 현재 조작

G: 일반 → 브러시 → 바닥 타일 → 일반. Esc: 종료.

브러시: 왼쪽 버튼으로 드래그, 1~3 재질 색, 0 지우개, [ / ] 크기, Ctrl+Z / Ctrl+Y 되돌리기·다시 실행.

바닥 타일: 클릭으로 미리보기 시작, 마우스로 위치 선택, R 회전, Enter 확정, 오른쪽 클릭 취소. H는 가리킨 타일 보관, U는 보관한 첫 타일 꺼내기, V는 가리킨 타일 이동, Shift+클릭은 제거. 장식용 원형 기능으로 상점·재화 시스템은 추가하지 않았다.

## 저장과 복구

파일 버전은 2. 이전 버전은 `_before_terrain_v1.sav` 원본을 보관한다. 게임 스레드에서 상태를 한 번 직렬화한 후 파일 쓰기를 순서대로 처리한다. 연속 요청은 마지막 대기 스냅샷으로 모은다. `.pending` 작성과 `_previous.sav` 보관 후 현재 파일로 교체한다.

불러오지 못한 현재 파일은 손상 사본을 보관하고 직전 정상본 복구를 시도한다. 더 새로운 형식이나 복구 불가능한 파일은 덮어쓰지 않는다. 없어진 표면의 시설·바닥은 보관 상태로 복구하고, 적용하지 못한 도색 데이터는 남긴다.

## 성능 기준과 제한

기본 마스크는 표면당 128×128 RGBA8, 약 64KiB. 최대 16회 스트로크 전체 복사본을 보관한다. 브러시는 이동 거리 기준으로 찍으며 변경 사각형을 합쳐 프레임당 한 번 GPU에 부분 업로드한다. 초기 생성·불러오기·Undo/Redo는 전체 마스크를 갱신한다. GPU에서 CPU로 다시 읽는 작업은 없다. 타일은 3개 인스턴스 그룹으로 그린다. 경로 그래프는 고정 지형을 한 번 검사해 재사용한다.

이 수치는 구조상 예산이며 실제 FPS 보장이 아니다. 실제 게임·패키지 측정과 화면 확인 결과를 별도 기록한다. 현재 타일과 도색은 기능 검증용 색상이며 최종 아트·상점 UI가 아니다. Shipping용 미리보기와 대규모 맵의 청크 분할은 후속 범위다.
