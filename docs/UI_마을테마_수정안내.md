# 마을 테마 UI 수정 안내

2026-10-10. 사용자가 제시한 마을 컨셉과 가공 창 참고 이미지에 맞춰 AI가 구현한 적용안입니다. 최종 디자인 승인은 아직 받지 않았습니다.

## 무엇이 바뀌었나요?

- 둥근 한글 주아 글꼴을 실제 폰트 에셋으로 연결했습니다. 기호는 엔진의 대체 글꼴을 사용합니다.
- 크림색 창과 갈색 테두리, 푸른 제목줄, 금색 주요 버튼, 개별 그림 아이콘을 적용했습니다.
- 업그레이드는 시설 그림·레벨 목록과 선택한 시설의 상세 정보로 나뉩니다. 현재 시설 구성에서는 목록과 상세가 한 화면에 보입니다.
- 가공 화면은 재료 한도·공간 한도·최대 선택을 나누고 선택 횟수를 제작 버튼에도 표시합니다.
- 공통 외형은 HUD를 포함한 기존 편집 가능한 화면 12개의 설정에 연결했습니다. 상세 배치 개선과 실제 플레이 확인은 업그레이드와 가공 화면을 중심으로 진행했습니다.

## 어떤 에셋을 열면 되나요?

언리얼 아래쪽 콘텐츠 브라우저에서 Content → CozyRealm → UI로 이동하세요. 에셋을 두 번 누르면 편집 창이 열립니다.

| 바꾸려는 것 | 열 에셋 | 바꿀 항목 |
|---|---|---|
| 화면들이 함께 쓰는 외형 | Theme/DA_UiTheme_CozyVillage | Fonts(글꼴), Colors(색), Images(이미지), Button Styles(버튼 상태), Metrics(여백·간격) |
| 글꼴 파일 자체 | Fonts/F_Cozy_JuaFamily | 기본 글꼴의 Regular 항목. 제목·본문·숫자 크기는 테마의 Fonts에서 설정 |
| 시설 그림 | DA_UiTheme_CozyVillage → Images | Facility.Shrine, Facility.Mill, Facility.Nagaya, Facility.Hushinso, Facility.FieldOffice |
| 밀·밀가루·골드 등 아이콘 | DA_UiTheme_CozyVillage → Images | Icon.Wheat, Icon.Flour, Icon.Gold 등 |
| 창·제목줄·정보칸 | DA_UiTheme_CozyVillage → Images | Window, Header, Panel, Highlight |
| 시설 버튼 목록과 상세 내용 | Screens/DA_UiScreen_Upgrade | Elements(요소), Areas(자동 정렬 영역) |
| 가공 창 내용·순서·버튼 | Screens/DA_UiScreen_Processing | Elements, Areas |
| 화면 전체 위치와 기준점 | Widgets/WBP_Upgrade 또는 WBP_Processing | Designer(디자이너)에서 영역 위젯의 위치·크기·Anchors(기준점) |
| HUD의 위치 | Widgets/WBP_HUD | 기존 영역 상자의 위치. 사용자가 옮긴 위치는 유지 |

## 업그레이드 화면의 목록과 상세

DA_UiScreen_Upgrade의 Elements에는 아래 요소가 있습니다.

- FacilityCards: 첫 페이지 목록. Value Param의 Overview는 목록 페이지라는 뜻입니다.
- FacilityCard: 카드 한 개의 공통 모습. 그림 칸은 64×64, 카드는 184×108입니다. 글자·크기·그림 칸은 바꿀 수 있습니다.
- Facilities: 선택한 시설의 상세 목록. Value Param의 Detail은 상세 페이지라는 뜻입니다.
- FacTitle, FacDetail, FacBlock: 선택한 시설의 제목, 비용·조건·효과, 실행할 수 없는 이유입니다.
- FacStart: 실제 업그레이드 시작 버튼입니다. 기존 게임 기능의 시작 직전 검사를 그대로 사용합니다.
- BackToFacilities: 시설 목록으로 돌아가는 버튼입니다. 화면만 바꾸고 재료를 쓰지 않습니다.

시설 목록은 게임에서 업그레이드 가능한 시설을 읽습니다. 버튼 수는 코드에 고정하지 않았습니다. 목록의 작은 카드 배치는 CardRows 영역의 Wrap(줄바꿈)과 Gap(간격)으로 정합니다. 화면이 좁아지면 카드가 다음 줄로 이동합니다.

현재 화면에서는 기본 정보가 스크롤 없이 보입니다. 시설이 많이 늘거나 동시 작업·상세 안내가 많아지는 경우에는 기존 스크롤이 안전장치로 남아 있습니다.

## 가공 화면 수정

- Selected: 고른 레시피의 재료와 산출량, 한 회차 시간.
- MaterialLimit: ProcMaxInfo 값과 Materials 매개변수로 재료 한도를 읽습니다.
- SpaceLimit: ProcMaxInfo 값과 Space 매개변수로 미수령 공간 한도를 읽습니다.
- MaxInfo: 실제 최대 횟수. 최대값을 별도로 계산하지 않습니다.
- RunsText: 선택 횟수. {0}회라는 형식에서 {0}은 게임의 현재 선택 횟수입니다.
- Start: 선택한 횟수와 제작 시작·제작 추가 상태를 함께 보여 줍니다.
- Summary: 필요한 재료, 완료품, 예상 시간입니다.

제작 버튼은 재료 안내 바로 아래에 놓았습니다. 진행 중인 작업과 수령 영역은 그 아래입니다. 조건을 만족하지 않으면 기존 게임 규칙에 따라 버튼이 비활성화됩니다.

## 이미지 교체 순서

1. 플레이를 종료합니다.
2. 새 PNG를 콘텐츠 브라우저에 가져옵니다. 글자나 버튼 기능을 그림에 합치지 마세요.
3. DA_UiTheme_CozyVillage의 Images에서 해당 항목의 Image(이미지)를 새 텍스처로 바꿉니다.
4. 아이콘 비율이 다르면 화면 설정의 Image Fit(이미지 맞춤)을 Keep Ratio(비율 유지 맞추기)로 두고 Image Box(이미지 칸)를 조정합니다.
5. 배경과 버튼은 테두리를 보존하며 늘어나는 Box(상자) 방식입니다. 새 그림의 가장자리 두께가 다르면 Margin(늘리지 않을 가장자리 비율)도 확인하세요.
6. 저장하고 플레이해서 확인합니다.

자동 생성되는 카드와 요소 하나하나는 WBP의 Hierarchy(구조 목록)에 직접 놓인 항목이 아닙니다. Data Asset에서 내용·순서·자동 정렬을 바꾸고, WBP 디자이너에서는 그 목록을 담는 영역 상자를 옮깁니다. 자유 배치 요소는 기존 WBP 배치를 사용합니다.

## 보존과 검증

- 에디터 빌드 성공.
- 실제 플레이에서 후신소 메뉴 → 시설 카드 목록 → 제분소 상세 → 시설 목록 → 닫기를 확인.
- 현재 시설 구성에서 목록과 상세를 스크롤 없이 확인.
- 가공 화면의 최대 횟수와 선택 횟수·제작 버튼의 연동 확인(재료 22회, 공간 8회 → 최대 8회).
- 재료를 쓰는 제작·업그레이드 실행 버튼은 이번 디자인 검증에서 누르지 않았습니다.
- 기존 게임의 비용·시간·제작 대기·수령 규칙은 변경하지 않았습니다.
- 사용자 HUD 배치와 기존 보라색 덮어쓰기 값, AGENTS.md와 uproject의 기존 변경을 보존했습니다.
- 플레이 검증 전 저장 파일을 백업하고 검증 후 복원했습니다.
- Windows 녹화용 컴퓨터 제어가 시작하지 못했습니다. 영상 완료로 기록하지 않았고 실제 플레이 캡처만 남겼습니다.
- 노션은 이번 작업에서 수정하지 않았습니다.

새 원본 그림은 CozyRealm/SourceArt/UI/CozyTheme에 있고, 실제 교체용 텍스처는 UI/Textures/CozyTheme에 있습니다. 글꼴 원본과 OFL 라이선스는 SourceArt/UI/CozyTheme/Fonts에 있습니다.

글꼴 원본: [Google Fonts 주아 글꼴](https://github.com/google/fonts/blob/main/ofl/jua/Jua-Regular.ttf).


## 2026-10-10: 글자와 칸 맞춤 수정

사용자가 지적한 업그레이드의 ‘딱 맞게·단축 확정’ 글자 넘침을 계기로 전체 UI 설정을 점검했습니다. 이번 변경은 외형·배치 조정이며 게임의 재료, 비용, 제작·수령·판매 규칙을 바꾸지 않습니다.

- 공통 버튼 글꼴 크기를 23에서 20으로 조정했습니다. 글꼴 종류는 유지했습니다.
- 작은 고정 버튼 높이를 최소 56으로 늘리고 긴 문구 버튼의 폭을 보완했습니다.
- 내용에 맞춤 버튼은 공통 버튼 기본 크기를 **최소 크기**로 사용합니다. 글자와 아이콘에 더 큰 칸이 필요하면 자동으로 늘어납니다.
- 업그레이드 단축 조작, 창 아래 버튼, 가공 대기·취소, 주민 목록 등 가로 영역은 공간이 모자라면 다음 줄로 배치합니다.
- 안내문은 줄바꿈을 허용하고 숫자는 한 줄로 유지합니다. 창고 수량 열은 폭 160으로 조정했습니다.
- 시설 카드 폭은 210으로 늘려 ‘밭 관리 시설’ 이름을 담습니다.
- 디버그 미리보기의 상태 버튼은 3개씩 두 줄로 표시합니다.

### 나중에 직접 크기를 바꿀 때

1. 공통 글꼴: `UI/Theme/DA_UiTheme_CozyVillage` → `Fonts (글꼴)` → `Button (버튼)`의 크기를 바꿉니다.
2. 공통 최소 버튼 높이: 같은 에셋의 `Metrics (크기·여백)` → `Button Size (버튼 기본 크기)`의 Y를 바꿉니다. X=0은 너비를 내용에 맞춥니다.
3. 특정 버튼: `UI/Screens/DA_UiScreen_화면이름` → `Elements (요소 목록)`에서 버튼을 찾아 `Size Mode (크기 방식)`를 바꿉니다. `Content (내용에 맞춤)`은 글자에 따라 늘어나고, `Fixed (고정)`은 지정한 크기를 사용합니다.
4. 고정 크기를 쓸 때는 `Size (크기)`의 X·Y를 글자와 아이콘이 들어갈 만큼 확보합니다. 긴 안내문은 `Wrap Text (글자 줄바꿈)`을 켭니다. 수량·시간처럼 한 줄로 읽어야 하는 숫자는 줄바꿈을 끕니다.
5. 한 줄에 버튼이 너무 많으면 해당 `Areas (영역 목록)`의 `Flow (정렬 방향)`을 `Wrap (공간 부족 시 줄바꿈)`으로 바꿉니다.
6. WBP 디자이너에서 영역 상자를 드래그해 위치를 바꿉니다. 자동 생성 요소의 내용과 크기는 화면 Data Asset에서 관리합니다.

### 확인한 범위

공통 수정의 Live Coding 컴파일이 성공했습니다. 창고·시설 정보·가공·판매·업그레이드·밭 관리·나가야·방치 보상 8개 창을 진행 중·일시 정지·가득 참·잠김·수령 가능·비어 있음 6가지 상태로 전환해 총 48개 조합을 확인했습니다. 표시 중인 텍스트의 실제 필요 크기·배정된 칸과 버튼 배경 밖으로 나가는지를 비교한 결과 초과 항목은 0개였습니다. 배치 패널·회전·보관·확정·취소 버튼과 시설 메뉴도 별도로 확인했습니다. 스크롤 밖의 항목은 화면에 표시될 때 확인 대상이 됩니다. 긴 목록이나 모든 조건부 줄을 함께 보여주는 미리보기에서는 스크롤이 남을 수 있습니다.

검증 결과는 `docs/UI_칸맞춤_검증결과.json`, 확인 이미지는 `docs/images/ui-cozy-village/칸맞춤_*.png`에 있습니다.

정식 빌드가 성공했고 에디터 재실행 후 설정 저장을 확인했습니다. 디자이너에서 버튼 문구가 잘못 두 줄로 접히는 문제도 추가 수정했습니다. 버튼 문구는 한 줄로 유지하고 시설 카드의 명시적인 줄 구분은 보존합니다. 단축 조작의 짧은 이름·수량도 한 줄로 유지합니다. 사용자에게 저장 확인 창 처리를 요청했고, 사용자가 선택 항목을 저장한 뒤 빌드·재실행 검증을 이어갔습니다. 이번 추가 작업의 노션 기록과 Windows 녹화는 완료로 기록하지 않았습니다.
