## 구현과 변경 이유

기존 평면 좌표·시설 중심 높이 검사만으로는 같은 XY의 다른 층과 절벽 가장자리 지지를 구별하기 어려웠다. 표면 GUID와 전체 지지 검사, 별도 배치 미리보기, 높이별 길찾기를 추가했다. **기존 게임은 칸 기반 길찾기였으므로 NavMesh 전환 대신 이를 확장했다.** 설계 초안의 Nav Modifier 문구와 실제 구현을 혼동하지 않는다.

주요 파일은 `CozyRealm/Source/CozyRealm` 아래:

- `Environment/CozySurfaceComponent.*`: 표면 규칙, 지면 조회, 전체 지지, CPU 도색/GPU 표시. 기본 128² RGBA, 최신 코드는 변경 사각형 부분 업로드.
- `Environment/CozyPaintMask.*`: 합계 255의 기본+3색 가중치, 최대 16회 Undo. 최신 저장은 팔레트 버전 1과 GroundBase/Dirt/Stone/Sand ID 포함. 미지원 팔레트 적용 거부.
- `Environment/CozyGroundMesh.*`: 언덕·경사로 고정 메시.
- `Environment/CozySurfaceNavigation.*`: 100cm 노드, 20cm 연결 샘플, 35cm 턱, 경사·몸통 공간 검사, 시설 점유 반영. 고립 상판·공중 목표 연결 거부.
- `Environment/CozyFloorTiles.*`: 타일 GUID·표면·정의 ID·보관 상태, 3개 ISM 그룹, 충돌/길찾기 제외.
- `Core/CozyGroundEditing.cpp`: 편집 입력. 빠른 클릭 및 Ctrl+Z/Y 누락을 입력 이벤트 순서 처리로 수정했고 실제 조작 확인.
- `Estate/CozyEstateSubsystem.*`, `CozyEstateState.h`: 표면을 포함한 시설/바닥 상태와 복구. 최신 변경은 누락 시설·타일 정의 ID를 보존해 보관.
- `Estate/CozyEstateSaveIO.*`: 순차 비동기 쓰기, `.pending`, `_previous.sav`, 저장 요청 병합, 종료 시 Flush.
- `Environment/Tests/CozyTerrainTests.cpp`: 3개 자동 시험, 200회 도색 후 Undo 상한 16회 검사 포함.
- `CozyTerrainWorldCheck.cpp`, `CozyTerrainRecoveryCheck.cpp`, **신규 `CozyTerrainStressCheck.cpp`**: 격리 시험 콘솔 명령.

에셋 생성 스크립트는 `CozyRealm/SourceArt/Landscape/prepare_terrain_validation.py`, 원본 공통 함수 연결은 `install_ground_paint.py`. 기존 6개 Landscape 레이어·4계절 유지. 원본 재질 백업 `/Game/CozyRealm/Tests/Terrain/M_CozyLandscape_BeforeRuntimePaint`.

이미 해결한 실패: Python Rotator 축 순서(이름 인자로 수정), 맵 변경 미저장(`modify`와 명시적 `save_map`), 경사로 캡슐/낮은 턱을 벽으로 오인하던 검사. 실패 로그보다 후속 통과 로그를 우선한다.

1. AGENTS와 이 문서, 로컬 구현 기록, Notion 마지막 기록, 실제 변경을 읽는다. 빌드 성공과 실행 통과 버전을 반드시 구분한다.
2. 최신 에디터에서 `CozyRealm.Terrain` 자동 시험과 실제 검증 맵의 아래 3개 명령을 실행한다. **신규 반복 검사는 아직 한 번도 실행하지 않았다.**
   - `Cozy.TerrainVerify`
   - `Cozy.TerrainRecoveryVerify` — 최신 누락 에셋·리비전 항목을 실제 실행해야 함.
   - `Cozy.TerrainStressVerify` — 타일 설치/삭제·도색/Undo 200회, 개수 복귀와 50회/200회 프로세스 메모리 비교. 증가 32MiB 초과 시 실패하는 짧은 회귀 검사이며 장기 누수 보장은 아님.
3. 위 명령은 `-CozyTerrainTest`와 `UserDir`에 `TerrainPlayUser` 또는 `TerrainPackageUser`가 있어야 동작한다. 월드/반복 검사는 `L_TerrainValidation`에서만 동작한다. 반복 검사 위치 `(900,100,420)`에 기존 타일이 있으면 조용히 반환하므로 **새 시험 폴더**를 사용하고 `TerrainStressCheck.txt` 생성까지 확인한다. 실사용 저장에 실행하지 않는다.
4. 최신 게임 실행 파일로 Development 패키지를 다시 만든다. 기존 패키지는 최신 소스와 다르다. 기본 맵과 검증 맵을 모두 포함한다.
5. 최신 패키지 실제 화면에서 부분 도색 표시, Undo/Redo, 지우개, 평지·언덕 분리, 타일 보관/꺼내기/취소, 타일 위 시설, 타일 회수 시 시설 유지, 계절, 언덕 보행, 저장·종료·재실행을 확인하고 녹화한다. 실제 활성 생산/업그레이드/예약이 있는 시설의 이동 보존도 보강한다.
6. 연결된 지면 경계를 브러시가 가로지를 때 양쪽 연속성 및 Undo 작업 단위가 설계와 맞는지 점검한다. 현재 입력은 커서의 표면이 바뀌면 직전 표면 스트로크를 끝내고 새 표면에서 시작한다. 수직 절벽·가파른 경사 도색은 MVP 제외다.
7. 최신 빌드로 CPU/GPU/메모리/저장 프레임 측정을 갱신한다. 검증된 조건만 체크하고 카드 완료 여부를 판단한다. 그 다음 기존 Notion의 구매·꾸미기 점수 또는 최종 UI/아트 작업을 확인한다. 임의의 새 카드부터 만들지 않는다.

## 빌드·검증 실행 참고

에디터/게임을 정상 종료한 뒤 엔진 `Engine/Build/BatchFiles/Build.bat`로 각각 `CozyRealmEditor Win64 Development`, `CozyRealm Win64 Development`, `-Project=<uproject> -WaitMutex -NoHotReloadFromIDE -NoUBA -MaxParallelActions=2`.

자동 시험은 UnrealEditor-Cmd에 `-unattended -NullRHI -ExecCmds="Automation RunTests CozyRealm.Terrain;Quit" -TestExit="Automation Test Queue Empty" -ReportExportPath=<격리 보고 폴더>`를 사용했다. 성공은 로그의 개별 Result=Success와 TEST COMPLETE EXIT CODE 0으로 확인한다.

패키지는 RunUAT `BuildCookRun -project=<uproject> -noP4 -platform=Win64 -clientconfig=Development -skipbuild -cook -iterate -stage -pak -archive -archivedirectory=E:/Project/UE5_CozyRealm/Builds/TerrainDevelopment -map=/Game/CozyRealm/Maps/L_Estate+/Game/CozyRealm/Tests/Terrain/L_TerrainValidation -utf8output -unattended`.

실행 진입점은 `Builds/TerrainDevelopment/Windows/CozyRealm.exe`를 사용했다. 내부 Binaries 실행 파일 직접 시작은 초기 실행이 매끄럽지 않았고, 루트 런처는 정상 실행했다. `Builds/TerrainDevelopment/지형_기능_체험.cmd`는 검증 맵과 별도 TerrainTryUser 저장으로 실행하는 편의 파일이며 이 파일 자체는 아직 실행 검증하지 않았다.

에디터/컴파일러는 HDD의 큰 PCH를 처음 읽을 때 느릴 수 있다. UBA는 -NoUBA에서도 로컬 캐시를 사용하므로 엔진/로컬 캐시 접근 권한이 필요했다. 소스를 컴파일 중 동시에 수정하지 않는다.

## 조작과 현재 MVP 제한

G: 일반→브러시→타일. Esc 종료. 브러시 1/2/3 색, 0 지우개, [ ] 반경, 왼쪽 드래그, Ctrl+Z/Y. 타일 클릭 미리보기, R 회전, Enter 확정, 우클릭 취소, H 가리킨 타일 보관, U 첫 보관 타일 꺼내기, V 이동, Shift+클릭 삭제. 시설은 B에서 드래그 후 UI 확정. 높은 언덕의 확인 버튼이 HUD와 겹치면 줌아웃해 조작했다(후속 UI 개선 대상).

타일·도색은 시험용 색상/기본 도형이다. 최종 텍스처 아트·상점·재화·꾸미기 점수·높은 데크·다리는 미구현 범위. 미리보기는 Development DebugDraw 기반이므로 Shipping 배포 완성으로 표현하지 않는다. 카메라가 높이를 따라가는 개선은 하지 않았다.
