# UI 아이콘 공유 시트 사용 안내

2026-10-11. 사용자 요청으로 기존 아이콘과 새 그림 아이콘을 종류별 공유 텍스처로 전환했다. 구현과 이미지 제작은 Codex가 수행했다. 디자인 최종 승인을 뜻하지 않는다.

## 지금 사용하는 방식

그림 21개를 게임용 텍스처 3장에 담았다. 같은 그림을 사용하는 여러 이름은 같은 칸을 공유하므로 기존 이름 35개를 유지한다.

| 종류 | 게임용 시트 | 크기 | 그림 수 |
|---|---|---|---|
| 자원 | `T_CozyAtlas_Resources` | 384×384 | 9 |
| 시설 | `T_CozyAtlas_Facilities` | 512×256 | 8 |
| 기타 | `T_CozyAtlas_Common` | 256×256 | 4 |

각 칸은 128×128이며 그림은 최대 112×112로 맞추고 주변에 최소 8픽셀 여백을 둔다. 32~64 크기의 일반 UI 아이콘용이다. 앞으로 큰 삽화 크기로 사용할 때는 게임용 해상도를 다시 정해야 한다.

팥·쌀·쌀가루·잠금·미리보기는 기존 밀·밀가루와 어울리는 그림으로 교체했다. 자물쇠와 돋보기는 현재 화면에서 사용되지 않아 실제 사용 화면 검증을 완료한 것으로 기록하지 않는다.

창·패널·칩·제목 배경·강조 배경과 버튼 상태 이미지는 별도 텍스처로 유지했다. 이런 배경은 늘어나는 방식이 아이콘과 다르다.

## 화면에서 아이콘을 고를 때

화면 데이터 에셋의 `Image` 선택 목록에서 기존처럼 `Icon.Wheat`, `Icon.Flour`, `Icon.RedBean`, `Facility.Mill`, `Menu.@Row` 등을 선택한다. 화면마다 좌표를 직접 적을 필요가 없다.

공통 테마 `DA_UiTheme_CozyVillage`의 ‘3 이미지’에 두 목록이 있다.

- `Images (이미지 이름표)`: 기존 배경 이미지.
- `Atlas Images (공유 시트 아이콘 이름표)`: 아이콘 이름 → 공유 텍스처와 해당 칸의 좌표.

공유 아이콘의 `Texture`는 3장 중 하나이고, `Origin`과 `Size`는 픽셀 단위이다. `Texture Size`는 시트 전체의 원본 크기이며 가져오기 도구가 기록한다. 텍스처 준비 중 임시 크기가 반환되거나 플랫폼에서 해상도가 줄어도 이 원본 크기로 영역을 계산한다. 같은 이름이 두 목록에 있으면 유효한 공유 시트 항목이 우선한다. 좌표가 잘못된 경우 기존 이미지가 있으면 그 이미지로 돌아가고, 없으면 표시하지 않는다.

`Tint`는 아이콘 색상이다. 시트를 다시 가져와도 테마에 직접 바꾼 기존 이름별 Tint를 유지한다. 글자 크기·버튼 크기·HUD 위치는 이 설정과 별개이다.

## 원본 그림을 바꿀 때

원본 위치는 `E:\Project\UE5_CozyRealm\CozyRealm\SourceArt\UI\CozyTheme`이다.

- 기존 그림: `T_Cozy_Wheat.png`, `T_Cozy_Flour.png` 등 개별 PNG.
- 새 그림 5개: `Painted\T_Cozy_RedBean.png`, `Painted\T_Cozy_Rice.png`, `Painted\T_Cozy_RiceFlour.png`, `Painted\T_Cozy_Lock.png`, `Painted\T_Cozy_Preview.png`.
- 시트 원본: `Atlases` 폴더의 PNG 3장과 `atlas_manifest.json`.
- 기존 이름 연결: `atlas_aliases.json`.

개별 원본을 수정한 다음 아래 순서로 갱신한다.

1. 언리얼 플레이를 종료한다.
2. Pillow가 설치된 일반 Python에서 `pack_icon_atlases.py`를 실행한다. 원본의 투명 여백을 기준으로 크기와 위치를 맞추고 3장을 다시 만든다. Painted 폴더의 기존 파일을 자동으로 덮어쓰지 않는다.
3. 언리얼 아래쪽 명령 입력란에 다음을 입력한다.

```text
py E:/Project/UE5_CozyRealm/CozyRealm/SourceArt/UI/CozyTheme/import_icon_atlases.py
```

4. 가져오기 완료 메시지를 확인한다. 이 도구가 텍스처 3장과 테마의 이름·좌표를 함께 저장한다. 자동화된 가져오기를 사용해 같은 에셋 이름을 갱신한다.
5. 플레이와 미리보기에서 해당 아이콘이 제대로 보이는지 확인한다.

한 장을 다시 개별 텍스처로 잘라 넣는 방식이 아니다. 게임에서는 `FSlateBrush`의 UV 영역으로 한 장의 특정 칸만 표시한다. Paper2D 플러그인이나 아이콘마다 별도 머티리얼을 추가하지 않았다.

아이콘을 새로 추가할 때는 제작 도구의 종류별 목록과 `atlas_aliases.json`의 이름 연결을 추가해야 한다. 기존 이름이 다른 칸으로 이동하더라도 가져오기 도구가 좌표를 다시 기록한다. 현재 개수를 검사하는 `ActiveTheme` 자동 검증도 의도한 새 개수로 갱신한다.

## 용량과 검증 범위

아이콘 텍스처 참조 수는 21장 → 3장이다. 원래 텍스처 크기를 준비 완료 후 편집기 내부에서 확인했으며, 같은 RGBA8·밉맵 없음 조건으로 계산한 픽셀 용량은 11.25MiB → 1.3125MiB이다. 약 88% 감소는 **공유 시트 전환과 게임용 해상도 조정의 합산 효과**다. 아틀라스로 묶기만 했을 때의 감소율이 아니다.

실제 GPU 메모리, 그리기 횟수, 프레임 속도, 패키지 용량 감소율은 측정하지 않았다. 원본 텍스처 에셋은 보존했으므로 다른 에셋의 참조나 패키징 설정에 따라 여전히 패키지에 포함될 수 있다. 사용하지 않는 에셋의 삭제는 별도 참조 검토 후 결정한다.

정식 편집기 빌드가 성공했고 공유 영역·비율·기존 이미지 호환성 검증과 현재 테마의 35개 이름 검증 2개가 모두 통과했다. 편집기를 재실행한 직후에도 두 검증이 다시 통과했다. 실제 HUD·창고·제분소 메뉴에서 아이콘을 확인하고, 진행 중 미리보기의 창 8개를 직접 열어 캡처를 검사했다. 이번 세션의 Python 위젯 기하 검사에서 유효한 대상이 잡히지 않아 ‘글자 초과 0건’이라는 자동 판정을 검증 결과로 사용하지 않았다. 이전 48개 상태 검사를 이번 작업에서 다시 했다고 기록하면 안 된다.

사용자 글꼴·HUD 위치·보라색 OnPoint·게임 규칙을 수정하지 않았고, 검증 전 저장 파일을 백업 후 복원해 파일 해시가 일치함을 확인했다. 이번 작업의 실제 Windows 플레이 녹화와 노션 갱신은 수행하지 않았다. 커밋·푸시·PR·병합도 수행하지 않았다.
