# 커밋 규칙 — CozyRealm

Conventional Commits를 바탕으로, 게임 개발용 타입과 작업 카드 연결을 더한 규칙이다.

## 형식

```text
타입(범위): 요약

본문 (무엇을, 왜 바꿨는지)

Card: 제작 보드 카드 이름
Test: 무엇으로 확인했는지
```

- **요약:** 한국어, 50자 안쪽, 마침표 없음. "~ 추가", "~ 수정", "~ 제거"처럼 끝낸다.
- **타입·범위:** 영어 소문자.
- **본문:** 한 줄에 하나씩 `-`로. 요약만으로 충분하면 생략한다.
- **Card:** Notion 제작 보드의 카드 이름 그대로 (티켓 번호 역할). 카드가 없는 작업이면 생략.
- **Test:** 기획서 ⚙️ 통과 조건이나 빌드·실행으로 확인한 내용. 확인하지 않았으면 `Test: 미확인`이라고 쓴다.
- 커밋 하나에는 한 가지 일만 담는다. 기능과 에셋, 수치 조정은 따로 커밋한다.

## 타입

| 타입 | 언제 | 예시 |
|---|---|---|
| `feat` | 새 기능·시스템 | `feat(production): 오니비 배치 시 자동 생산 추가` |
| `fix` | 버그 수정 | `fix(save): 방치 보상 시간 계산 오류 수정` |
| `art` | 모델·텍스처·애니메이션·이펙트 추가·교체 | `art(resident): 기본 오니비 메시·애니메이션 추가` |
| `balance` | 데이터 테이블 수치 조정 | `balance(recipe): 당고 가공 시간 45초 → 40초` |
| `level` | 맵·배치·라이팅 | `level(realm): 시작 영지 12×12 블록아웃` |
| `ui` | 화면·HUD·위젯 | `ui(hud): 골드·재료 개수 표시 추가` |
| `refactor` | 동작은 같고 구조만 개선 | `refactor(grid): 좌표 계산을 서브시스템으로 분리` |
| `perf` | 성능 개선 | `perf(production): 생산 틱을 1초 간격으로 묶기` |
| `test` | 테스트·디버그 도구 | `test(debug): 시간 배속 디버그 메뉴 추가` |
| `build` | 빌드 설정·플러그인·엔진 설정 | `build(plugin): Unreal MCP 플러그인 추가` |
| `docs` | 기획·문서 | `docs: GPT 프로젝트 지침 갱신` |
| `chore` | 그 밖의 설정·정리 | `chore(git): Git LFS 규칙 추가` |

## 범위 (자주 쓰는 것)

`project` · `production`(생산) · `recipe`(가공) · `facility`(시설) · `upgrade` · `resident`(주민) · `recruit`(영입) · `grid`(배치) · `decor`(꾸미기) · `expedition`(원정) · `equipment` · `save` · `time`(게임 시간·방치) · `camera` · `input` · `hud` · `ui` · `data`(데이터 테이블) · `debug` · `realm`(영지 맵) · `plugin` · `git`

새 시스템이 생기면 여기에 추가한다.

## 예시

```text
feat(production): 오니비 배치 시 자동 생산 추가

- 시설 창에서 주민 선택 → 10초마다 밀 +1
- 생산 주기는 DT_Facility에서 읽음

Card: 기능 1: 자동 생산
Test: 통과 조건 확인 (10초마다 밀 +1 표시)
```

```text
balance(upgrade): 밀밭 업그레이드 비용 곡선 완화

- 비용 = 20 × 1.5^(레벨-1) → 20 × 1.4^(레벨-1)
- Lv10 비용 약 769 → 약 413골드

Card: 10주차 기능 2: 밸런스 · 버그 수정
Test: 밸런스 편집기에서 시간당 수입 대비 확인
```

## 브랜치 · PR

- **기능·에셋 카드 하나 = 브랜치 하나 = PR 하나.** 브랜치 이름은 `타입/짧은-영어-이름` (예: `feat/auto-production`, `art/onibi-basic`, `balance/upgrade-curve`).
- **문서 수정·오타 같은 작은 변경**은 main에 바로 커밋해도 된다.
- **PR 제목**은 대표 커밋과 같은 형식(`타입(범위): 한국어 요약`). 설명에는 요약 · 변경 내용 · 확인(통과 조건 체크박스) · `Card:`를 쓴다.
- **머지** 후에는 원격·로컬 브랜치를 지운다. 기록은 PR에 남는다.
- AI에게 맡길 때: "브랜치 만들어줘: (카드)" → 작업 → "커밋해줘" → "PR 만들어줘" → "머지해줘" (GitHub CLI `gh` 사용).
